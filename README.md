# UDP Hole Punching - Техническое Задание

## 1. Описание проекта

Реализовать Р2Р соединение между клиентами, которые подключены по UDP к общему серверу. Необходимо создать клиент-серверное приложение, в рамках которого каждый из клиентов подключается по UDP протоколу к серверу, а затем начинает hole punching’ ом узнавать айпи и порт другого клиента, к которому нужно получить доступ.

## 2. Цель проекта

Реализовать P2P соединение, которое позволяет:

- Установить соединение между UDP клиентами через NAT
- Использовать hole punching технику для проникновения через NAT
- Обеспечить прямое взаимодействие клиентов между собой без промежуточного сервера
- Реализовать QUIC-подобный протокол для общения между клиентами

## 3. Компоненты системы

### Сервер

**Функции:**

- Прием регистрации клиентов (аналог STUN)
- Хранение информации о подключенных клиентах (IP, порт, username, PeerID)
- Предоставление списка активных клиентов
- Координирование процесса hole punching между клиентами (при изменении IP и/или порта у клиента P2P соединение не разрывается а обновляется)

### Клиент

**Функции:**

- Регистрация на сервере (отправка Binding Request)
- Получение списка подключенных пользователей
- Инициирование hole punching с целевым клиентом
- Прием и отправка данных другим клиентам (P2P режим)

## 5. Сценарии использования

### Сценарий 1: Регистрация клиента

```
1. Client_A запускается
2. Client_A отправляет Binding Request серверу
3. Server регистрирует Client_A (IP:Port и выдает PeerID если такого клиента не было)
4. Server отправляет PeerID и публичные IP:Port обратно 
```

### Сценарий 2: Получение списка клиентов

```
1. Client_A отправляет List Request серверу
2. Server возвращает список всех активных клиентов
3. Client_A выводит список доступных пользователей
```

### Сценарий 3: Установление P2P соединения (Hole Punching)

```
1. Client_A выбирает Client_B из списка
2. Client_A отправляет Connect to Client Request к серверу
3. Server отправляет Client_A адрес Client_B
4. Server отправляет Client_B адрес Client_A
5. Client_A и Client_B начинают отправлять sync packets друг другу
6. После открытия портов - прямое P2P соединение установлено
7. Client_A и Client_B обмениваются данными напрямую
```
